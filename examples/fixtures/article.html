Rate limiting guide

Overview

Every API key has a request budget that refills continuously. Budgets are tracked per key and per region, so traffic in one region never drains another.

When a client exceeds its budget, the API rejects further requests until the budget refills.

Retry behaviour

Rejected requests receive status 429 and a Retry-After header.

Clients should wait for the number of seconds given in the Retry-After header before retrying. Retrying sooner counts against the budget and extends the wait.

SDKs implement this automatically, with a cap of 60 seconds per wait.

Errors

Other 4xx errors are not retried, because repeating the same request cannot succeed.
